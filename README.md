# DNScope 🔍

![Banner](images/ban.png)

A Python tool for analysing **DNS Internet Background Radiation (IBR)** from PCAP/PCAPNG files. Built as part of the **Bachelor Project in Cyber Security at Noroff University College** using the [Cloud Telescope](https://doi.org/10.21227/zkyy-gk56) dataset.

**Author:** Mohammed Altanib

---

## Overview

DNScope extracts, structures, and analyses DNS traffic from raw passive packet captures. The project was developed to support three research questions about DNS activity within Internet Background Radiation (IBR).

| RQ  | Question |
|-----|----------|
| RQ1 | DNS share of IBR across regions and time |
| RQ2 | Dominant DNS query types, response codes, queried domains, and query/response balance |
| RQ3 | Source networks and geographic distribution of DNS traffic |

The main workflow converts raw PCAP/PCAP.GZ files into structured Parquet data, then uses standalone scripts and a supporting Jupyter Notebook to reproduce the analysis.

## Scripts

| Script | Purpose |
|--------|---------|
| `fast_extract.py` | Extracts DNS packets from one or more PCAP/PCAP.GZ files using `tshark` and writes DNS-only Parquet output |
| `csv_to_parquet_addcols.py` | Converts CSV to Parquet and adds `src_24` and `eTLD+1` columns |
| `merge.py` | Merges multiple Parquet files into a single merged Parquet dataset |
| `Results.py` | Combined analysis workflow used during development and notebook exploration |
| `dnscope_mini_figs.py` | Generates additional figures from merged Parquet data |
| `build_rq1_all_regions.py` | Builds `rq1_all_regions.parquet` for RQ1 from the original PCAP files |
| `RQ1.py` | Reproduces the RQ1 DNS share analysis |
| `RQ2.py` | Reproduces the RQ2 DNS query/response structure analysis |
| `RQ3.py` | Reproduces the RQ3 source network and geographic analysis |

## Research Question Scripts

The original analysis was developed in `Results.py` and in the accompanying Jupyter Notebook.

For clarity and artefact review, the research-question logic has also been separated into standalone scripts:

- `RQ1.py`: uses `rq1_all_regions.parquet` to plot DNS share over time and overall DNS share by region.
- `RQ2.py`: uses `e3_merged.parquet` to analyse QTYPE distribution, RCODE distribution, queries vs responses, and top eTLD+1 domains.
- `RQ3.py`: uses `e3_merged.parquet` to analyse source /24 prefixes and country-level distribution when a country column is available.

For RQ3 country-level results, the country mapping was produced during preprocessing/notebook work using the external MaxMind database file `GeoLite2-Country.mmdb`. The standalone `RQ3.py` reads an existing country column if it is present in the merged Parquet file.

## Rebuilding the DNS Merged Dataset

The merged DNS dataset is expected to be named:

```text
e3_merged.parquet
```

This file is used by `RQ2.py`, `RQ3.py`, and `Results.py`.

Example extraction command using `fast_extract.py`:

```bash
python fast_extract.py e3/example.pcap.gz \
  --out-parquet dataset3_parquet/e3/example.parquet \
  --region eu-west-1a \
  --week-id 2023W51
```

After multiple Parquet files are created, they can be merged into one dataset using `merge.py` or an equivalent DuckDB merge command.

The final merged DNS dataset should be placed in the project root as:

```text
e3_merged.parquet
```

## Rebuilding RQ1 Intermediate File

RQ1 does **not** rely only on `e3_merged.parquet`.

RQ1 measures the DNS share of total IBR traffic:

```text
dns_share = dns_pkts / total_pkts
```

For this reason, RQ1 requires an intermediate file named:

```text
rq1_all_regions.parquet
```

This file is generated from the original PCAP files by `build_rq1_all_regions.py`.

The script reads files from:

```text
e3/
```

and counts:

- total packets per region/time bin
- DNS packets per region/time bin

It then calculates `dns_share` for each region and hourly time bin.

Run:

```bash
python build_rq1_all_regions.py
```

After this step, the following file is created:

```text
rq1_all_regions.parquet
```

Then run:

```bash
python RQ1.py
```

This produces:

```text
Figure_RQ1_1_timeseries_top_regions.png
Figure_RQ1_2_bar_overall_share_top15.png
```

## Running RQ2

RQ2 depends on:

```text
e3_merged.parquet
```

Run:

```bash
python RQ2.py
```

The script analyses:

- top eTLD+1 domains
- DNS response codes in responses only
- DNS query types grouped as known vs other
- query vs response balance using a log-scale plot

---

## Running RQ3

RQ3 depends on:

```text
e3_merged.parquet
```

Run:

```bash
python RQ3.py
```

The script analyses:

- top source /24 prefixes
- source /24 share
- source country distribution, if a country column exists in the merged Parquet file

If country-level mapping needs to be rebuilt, place the external MaxMind database in the project root:

```text
GeoLite2-Country.mmdb
```

## Combined Notebook-Style Analysis

`Results.py` provides a notebook-friendly combined workflow.

Example:

```python
from Results import dnscope_mini

results = dnscope_mini(
    src="e3_merged.parquet",
    out="run_out",
    topn=20,
    show=True
)

daily       = results["daily"]
regional    = results["regional_daily"]
qtype_rcode = results["qtype_rcode"]
daily_any   = results["daily_any"]
top_src24   = results["top_src24"]
top_etld1   = results["top_etld1"]
```

## Dataset

Developed and tested using the [Cloud Telescope IBR Dataset](https://doi.org/10.21227/zkyy-gk56), collected between October 2023 and March 2024 across 26 AWS regions, comprising approximately 530 million packets.

The raw PCAP files are not included in this repository because of file size and privacy limitations.

## Notes on Privacy

The analysis is based on passive IBR data. Source IP addresses are reduced during processing where possible, for example by using IPv4 `/24` aggregation and country-level summaries. The repository is intended to support reproducibility without publishing raw packet captures.
